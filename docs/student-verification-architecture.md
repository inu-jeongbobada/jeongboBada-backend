# 재학 확인(학생 인증) 아키텍처

착수 전, 구조를 먼저 문서로 정리한다. 실제 구현은 이 문서를 기준으로 진행한다.

## 배경

- 에타처럼, 회원가입한 사람이 실제 인천대 재학생인지 확인이 필요함
- 학생이 재학증명서/학생증 등 증빙 이미지를 업로드 → 관리자가 직접 검토 → 승인/거절
- 증빙 파일은 S3에 저장

## 구성 요소 (예정)

| 구성 | 역할 |
|---|---|
| S3 연동 | AWS SDK로 증빙 이미지 업로드/저장. 버킷/IAM 권한 설정 필요 |
| 파일 업로드 API | 학생이 증빙 이미지를 올리는 API. presigned URL 방식(클라이언트가 S3에 직접 업로드) vs 서버 경유 업로드 중 택1 결정 필요 |
| `User`의 인증 상태 필드 | `VerificationStatus`(예: `PENDING`/`APPROVED`/`REJECTED`) enum 컬럼 추가 |
| 관리자 검토 API | 대기 중인 인증 요청 목록 조회, 승인/거절 처리. **`docs/auth-architecture.md` 6번(권한 관리) 작업에 의존** — `hasRole("ADMIN")`으로 보호해야 함 |

## 다른 작업과의 관계

- **권한 관리(ADMIN)가 선행돼야 함** — 관리자 검토 API는 로그인한 사람이 ADMIN인지 확인해야 하는데, 그 인프라(`JwtAccessDeniedHandler`, 권한 체크)가 먼저 있어야 이 API를 안전하게 보호할 수 있음
- S3는 이 기능 전용이 아니라, 나중에 다른 도메인(교수 이미지, 커뮤니티 게시글 첨부파일 등)에서도 재사용될 수 있는 공용 인프라 — S3 연동 자체는 `global` 쪽에 범용으로 만들어두는 게 나을 수 있음

## 결정이 필요한 사항 (구현 전 확인)

- [ ] 미인증(`PENDING`) 상태 유저가 로그인은 가능하게 할지, 아예 막을지
- [ ] 거절(`REJECTED`) 상태 유저 재신청 허용 여부
- [ ] 증빙 파일 업로드 방식 — presigned URL(클라이언트→S3 직접) vs 서버 경유
- [ ] 증빙 파일 보관 기간 및 삭제 정책 (개인정보/민감정보라 무기한 보관은 지양)
- [ ] S3 버킷 접근 권한 — public 금지, IAM/버킷 정책으로 서버(또는 presigned URL)만 접근 가능하게

## 상태

### 1. S3 연동
- [ ] AWS SDK 의존성 추가
- [ ] S3 버킷 생성 및 IAM 사용자/권한 설정
- [ ] `application.yml.example`에 S3 설정 키 추가 (액세스키는 당연히 빈 값, `docker-compose.yml`/`.env.example`도 같이 — `CLAUDE.md`의 설정값 체크리스트 참고)
- [ ] 파일 업로드/다운로드 유틸 클래스

### 2. 재학 확인 플로우
- [ ] `User` 엔티티에 `VerificationStatus` 필드 추가
- [ ] 증빙 파일 업로드 API
- [ ] 관리자용 대기 목록 조회 API (ADMIN 권한 필요)
- [ ] 관리자 승인/거절 API
- [ ] 미인증/거절 상태 유저의 로그인 정책 반영
